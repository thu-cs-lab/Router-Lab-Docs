# 第四阶段：自主探索与高级网络功能实现

前三个阶段帮助大家掌握 P4 编程、Tofino 硬件操作和完整的转发流程。第四阶段将这些技能用于一个自己感兴趣的问题：从网络场景中提出问题，阅读相关研究，设计可在交换机上运行的方案，再用实验说明方案是否有效、适用于什么条件、还存在哪些限制。

**本阶段鼓励自主选题、自由探索前沿问题。助教介绍的方向仅供参考，不限定选题范围；往年已经选过的题目今年不再选用。** 本文档收录的历年项目用于了解项目背景、实现过程和实验结果，不作为今年的待选题目。大家可以围绕新的研究问题或应用场景设计原型；选题前请与助教讨论问题、工作量、实验资源和验证方法。

## 实验目标

本阶段希望大家完成一次从想法到实验结论的项目实践：

* **提出问题**：说明应用场景、现有方法及其不足，解释为什么值得在可编程交换机上研究。
* **设计方案**：理解相关论文中的机制，划分数据平面、控制平面和端系统的职责，确定能够完成的原型范围。
* **实现系统**：在真实 Tofino 环境中实现关键机制，处理计算、存储、流水段和接口的约束。
* **验证与分析**：设计能检验核心机制的实验，与基线比较，解释结果、失败场景和方案边界。

选题名称的复杂程度、代码量或是否使用了某个热门术语，都不能代替对问题和实现的理解。一个目标明确、验证充分的小项目，也可以体现有价值的探索。

## 如何开始选题

建议阅读网络领域前沿论文、观察实际应用需求，寻找最新问题。历年项目帮助大家了解如何把问题转化为方案和实验，选题时仍需明确自己的研究对象与目标。

选题时建议先回答以下问题：

1. **想解决什么问题？** 描述具体场景，给出可以观察或测量的现象。
2. **已有方法如何解决？** 找到直接相关的论文、协议或开源实现，明确准备复现、修改或扩展哪一部分。
3. **为什么需要交换机？** 说明在数据包经过网络时执行该功能的收益，以及放到控制面或主机上的取舍。
4. **能在现有平台实现吗？** 提前检查目标芯片、SDE、端口和主机需求；用小程序验证关键操作能否编译并运行。
5. **怎样证明它有效？** 先选定基线、工作负载和指标，再决定实现范围。

建议把项目拆为“最小可验证目标”和“进一步探索”。先打通一个能够解释和测试的完整流程，再增加模型规模、协议能力或复杂负载。

## 时间安排

本阶段按以下校历周次开展，具体上课、汇报和验收时段见课程公告。

| 时间 | 安排 | 准备内容 |
|---|---|---|
| 第 8 周 | 助教介绍选题方向，启动调研 | 参考助教推荐选题开始探索选题方向 |
| 第 9～11 周 | 调研、方案设计 | 与老师和助教讨论选题 |
| 第 12～15 周 | **每周进行进度汇报** | 说明本周完成的内容、实验数据、遇到的问题和下一周计划；第 12 周应能清楚介绍选题与整体方案 |
| 第 16 周 | **实验验收** | 演示系统和关键实验，解释设计、实现、测试方法及结果 |
| 第 18 周 | 提交实验报告与代码 | 整理完整代码、运行方法、实验配置、结果分析和参考资料 |

每周汇报应围绕可检查的进展展开：一段已验证的数据面逻辑、一组下发成功的表项、一项基线实验，或一个已定位的问题。出现硬件资源不足、实验条件不满足等问题时，请及时沟通，调整范围。

## 实验环境与项目组织

实验以 Tofino 可编程交换机为主要平台，按选题需要使用控制面程序、平台容器和测试主机。平台的申请、容器连接和终端操作见[实验平台使用说明](../platform.md)，基础硬件操作可回顾[第二阶段总述](../tofino_operations.md)。

组队项目可以按算法、模块或测试任务分工，但需要尽早约定接口，定期合并和联调。每位成员都应理解项目的核心机制，并能解释自己实现和验证的部分。组队方式与人数请结合选题工作量和当年课程要求，与助教讨论确定。

## 汇报与提交内容

进度汇报、验收展示和最终报告可以围绕同一条主线组织：

* **背景与问题**：应用场景、研究动机、相关工作及项目目标。
* **方案与实现**：系统结构、关键算法、数据面与控制面的分工、硬件限制及解决办法。
* **实验与结论**：拓扑、负载、基线、指标、原始结果与分析，已验证的能力和已知限制。
* **复现与分工**：编译运行步骤、依赖、配置、测试脚本、结果生成方法，以及成员贡献。

参考论文、已有仓库或往年项目时，请标注来源，说明复用了什么、自己完成了什么。如果使用 AI 辅助调研、实现或调试，仍需核对协议与硬件行为，并能够解释代码和实验结果。
